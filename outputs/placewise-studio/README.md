The documentation uses a 272px desktop sidebar and a reading column capped at 1120px. Fourteen pages cover Figma status, foundations, icons, primitives, patterns and controls. At 850px, the sidebar becomes a modal menu. The sidebar Light/Dark switch and System control use the app's semantic tokens. Saved appearance wins; otherwise the OS determines the theme, with light as fallback. Theme changes preserve navigation position.

The documentation's live phone-control specimens use IosButton, Ionic forms and selection controls, lists, popovers, Ionicons and IonSpinner. The marketing Accordion example retains the existing Radix export; the documentation shell retains its existing primitives. The phone uses Ionic components for all applicable app UI, with shared adapters for buttons and contained popovers and direct Ionic imports for one-off compositions. Component tokens remain deferred. Studio compact buttons use 44px targets; some legacy landing-page controls still need migration from 34–40px.

The phone uses `@ionic/react` 9.0.4 in iOS mode for navigation (`IonHeader`, `IonToolbar`, `IonTitle`, `IonButtons`), its sidebar (`IonMenu`), app/map/keyboard actions (`IonButton`), lists and metadata (`IonList`, `IonItem`, `IonLabel`, `IonNote`, `IonBadge`), attachment and route-edit menus (`IonPopover`), and subject/neighborhood choices (`IonSelect`, `IonSelectOption`). Duration, interests, Coffee and text entry use `IonRadioGroup` / `IonRadio`, `IonCheckbox`, `IonToggle`, `IonInput` and `IonTextarea`. App icons use `IonIcon` with Ionicons; loading feedback uses `IonSpinner`.

[Ionic React](https://ionicframework.com/docs/react/add-to-existing) supplies third-party web components following iOS patterns. Preserve its component geometry and interaction states while applying Placewise's existing typography and colors. The app does not import UIKit, SwiftUI, SF Symbols or a Figma kit. The approved compact composer and conversation sizing remain app-specific; menus and popovers stay within the phone. Mapbox remains the map provider. Browser file/photo pickers and the real mobile keyboard remain OS features; the desktop keyboard is a simulation with Ionic buttons and dedicated rectangular keycaps, not standard app-button shapes. Tapping outside the keyboard and message field dismisses it while keeping the draft and allowing the tapped action. The marketing page and documentation shell keep their existing primitives.

Mockup contains the revised iPhone wireframe: map selection or a sample photo attaches a subject to the question; a short walk setup leads to an editable route preview and an active walk. Conversations preserve the selected subject, while returning to a walk preserves progress. The drawer shows Resume walk when applicable, a separate Plan a walk action, and three recent conversations labeled Chat or Walk with duration. View all opens the mixed history. New chat sits at the bottom right of the menu and opens a fresh chat on the current map without changing saved conversations or walk progress. Each walk retains its own route, conversation and progress. Inside the iPhone frame, the map fills the screen behind floating controls. Warm neutral surfaces, a restrained burgundy accent, clear type and a rounded composer refine the existing left menu and compact chat. There are no explanatory paragraphs. The page and phone respond to the theme controls. Reset mockup starts the current v4 study over; legacy v3/v2 data and theme preference are retained.

The map provider is Mapbox GL JS, using Light v11 and Dark v11 styles. Save a public Mapbox token as `VITE_MAPBOX_ACCESS_TOKEN` in `landing-page/.env.local`, then rebuild the Studio. Manage public tokens in [Mapbox's access-token console](https://console.mapbox.com/account/access-tokens/). Local environment files are ignored by Git. Public browser tokens are included in the built preview; use URL restrictions for deployed previews. Never put secret tokens in Vite variables. The user supplied the public token used by this local preview.

Without a configured token, the phone shows a Mapbox placeholder and the page links to setup. With a valid token, the map supports pan/zoom and three fixed selectable building subjects around Grand Central. Map position survives camera and planning detours; changing theme updates the map appearance. Mapbox logo and attribution controls remain visible. Double-click selects a named marker or arbitrary coordinate; touch and hold provides the iOS gesture. Enter/Space offers keyboard selection. Arbitrary points retain their coordinates without claiming to identify a building. Route generation remains simulated.

Photo and answer surfaces remain placeholder boxes. Routes, durations and walk progress are simulated, with no camera permissions, live location, routing, AI or account sync. Research saves under a v4 browser storage key after importing valid v3 chats, drafts, routes and walking progress. The older data remains untouched. Plan a walk in the menu creates a new plan; the contextual action within a Chat adds its first route to that conversation. Walk entries reopen routes, with their planning conversation accessible alongside. Starting a different walk pauses the previous one and retains its progress. These September 15 flows expand the earlier PRD with photo questions and walks. Documentation scenarios keep their state within the specimen. Studio fonts load from the web with fallbacks.

Run `npm run design-system:docs` or `npm run build:studio` to regenerate tokens, exports, compiled references and packaged sources. Rebuild and reload to update port 5177. To serve the packaged workspace from the project root, run `python3 -m http.server 5177 --bind 127.0.0.1 --directory outputs/placewise-studio`.

`npm run design-system:check` validates tokens/export and documentation freshness, including input/output hashes. It also checks 28 declared contrast pairs per theme. Review both themes, mobile navigation, menu focus and live controls after regeneration; freshness checks alone do not verify their interaction.

Chat opens automatically from the compact map composer. Messages can be sent with no attached place or photo; each message records the current neighborhood, Around Grand Central in this demo, as its fallback context. Selected place/photo context takes priority. Neighborhood context is saved with each message and shown above it without adding a composer chip. Selecting a place adds context without opening the keyboard. Tapping Message opens the keyboard while keeping the same compact composer size. One or two displayed lines fit inside the existing row; a third line grows the composer, up to a 120px input height. Pasting, deleting and changes in width recalculate wrapping. Sending closes the keyboard and expands the conversation. The map stays visible while typing and reading. The user requested restoration of this interaction after rejecting the September 16 draggable-sheet implementation.

The empty composer shows a mic and uses SpeechRecognition or webkitSpeechRecognition where supported. Speech becomes an editable draft, with Stop while listening and Send after completion; it never sends automatically. Recognition stops on typing, navigation, hiding the page or unmounting. Unsupported browsers and permission/service failures show an inline message. Actual microphone recognition depends on the browser and its speech service. The desktop keyboard supports letters, Shift, numbers, punctuation, spaces and deletion; actual touch devices use the native keyboard. Responses are labeled samples with source links. Follow-ups stay in the same conversation. Reload returns to the compact map while preserving chats, drafts and walks. Native device keyboard behavior remains unverified.

The composer + opens an iOS-mode `IonPopover` just above the composer, aligned with + and contained inside the phone frame. Camera, Photo and File stack as full-width 56px rows. Its position follows composer and phone resizing. Camera uses the existing sample capture. Photo and File open native pickers and attach filename, type and size metadata to the current chat. Dismissing the modal or cancelling a picker preserves the draft/context. The dialog traps keyboard focus, supports Up/Down and Home/End traversal, and returns focus to + after Escape or backdrop dismissal. Its short appearance transition respects reduced motion. File contents are not uploaded, stored or analyzed by this prototype.

The phone status bar and keyboard use original SVG exports from the user-supplied iOS 18 Figma kit. Keyboard spacing, home indicator, primary buttons, menus, list rows, form labels, navigation and switches follow the measured kit geometry while preserving Placewise colors, typography and interactions.
