# Place to chat flow

Target: the existing Placewise iOS phone mockup, the user's annotated map-first layout, and their explicitly approved six-step flow. Keep existing colors, typography and interaction behavior while replacing all applicable app UI with Ionic components as described below. Refero craft guidance supplies focus-visible, native input behavior and clear disabled states. No new visual direction or extra explanatory panels.

Double-click represents iOS long-press and adds location context without opening the keyboard. Single-click does not select. A rendered Mapbox place label supplies its name, coordinates and available identity/category metadata; a point without a place label keeps coordinate-only context. No persistent place bubbles are shown. Only the selected point gets a pin, with its name in the composer. Tapping Message opens the desktop keyboard simulation while retaining the compact composer; touch devices use their native keyboard. The composer grows only beyond two displayed lines. Messages can be sent without selecting a place or adding a photo. With no attachment, the message records the current neighborhood, Around Grand Central in this simulation. Explicit place or photo context takes priority. Sending closes the keyboard and expands the conversation with a concise sample response. Follow-ups remain in that conversation. Reload returns to the compact map state while keeping conversations and walks saved. A dismissed unsent draft is retained. Arbitrary map points never claim to identify a building automatically.

Typing and reading are distinct transient states; neither is persisted as the app's launch screen. The map remains visible throughout. Use the shared `IosButton` adapter for phone actions and retain the selected-context chip and history. Chat responses are marked as samples because no chat backend is connected. When the draft is empty or whitespace-only, a mic replaces Send. It starts browser speech recognition after a user tap, writes interim and final text into the draft, and shows Stop while active. Transcription never sends automatically. Typing, navigation, hiding the page and unmounting cancel the active session; late callbacks cannot change another conversation. Unsupported browsers and microphone errors show a concise recoverable message.

## September 16: Resizable chat sheet, withdrawn

The user rejected the implemented draggable interaction and requested the previous behavior. The automatic compact, typing and conversation states described above are the current interaction contract. The resizable-sheet notes below are retained as history and are no longer implementation requirements.

The user selected a draggable sheet with compact, half-height and expanded positions. Keep the existing Placewise phone, palette, type, map, composer and conversation content as the visual reference. Live Refero research was unavailable (inactive subscription); its bundled motion guidance supplies short, interruptible transitions and reduced-motion support.

Compact fits the handle, selected place and composer. Half uses half the phone's usable height. Expanded keeps at least 180px of map available so its controls and attribution remain accessible. The existing map container resizes with the sheet. Tapping Message opens half-height and the keyboard; sending returns to a reading size. The keyboard constrains the available height without replacing the chosen reading size. Dragging the handle dismisses the keyboard. The handle can also be tapped or operated with arrow keys, Home and End, and an explicit expand/collapse control supports single-click resizing. Only the handle captures vertical dragging; the conversation scrolls normally.

Sheet size is transient and separate from saved conversations. Resizing must preserve the draft and reading position. Collapse keeps the conversation available under the same handle; reload still opens compact. Keep camera, planner, route and walk layouts unchanged. Validate pointer dragging, cancellation, keyboard sizing, follow-ups, compact recovery, narrow layout and both themes in the rendered prototype.

## Location controls

Location controls use the existing map-first mockup as the visual reference: 48px round controls, restrained surfaces and the existing focus treatment. Mapbox camera rotation/reset and positioned markers supply the behavior; Refero live research was unavailable, so its bundled focus/touch guidance informed sizing. Blue is reserved for the location dot and heading cone, separate from the burgundy selected-place pin. The demo position is fixed near Grand Central with a northeast heading, clearly identified as simulated in accessible labels and handoff copy. No browser GPS or heading permission is requested. Compass resets north; recenter preserves bearing and restores a useful street-level zoom. On a short map, the compass and recenter sit side by side and redundant zoom buttons hide while scroll/pinch and keyboard zoom remain available.

## September 16: Attachment choices

The composer + opens an iOS-mode `IonPopover` above the composer, aligned with the + button and contained inside the phone frame. Camera, Photo and File use `IonItem` actions inside an `IonList`, forming a vertical list of 56px touch rows with leading icons and subtle dividers. The title is visually hidden; tapping outside or pressing Escape dismisses it. Measure after keyboard dismissal and track composer/phone resizing so it stays above short or multiline drafts. Reference lock: existing Placewise palette, typography and 8px spacing; use Ionic's iOS popover component with the shared phone-containment adapter. The explicit user correction sets the anchored vertical layout; bundled Refero craft guidance supplies visible keyboard focus, touch targets, initial focus, focus trapping and focus return. Closing or cancelling preserves the draft and selected context. Camera opens the existing sample capture flow. Photo opens an image picker and File an unrestricted file picker; selection attaches local filename/type/size metadata to the current conversation. No file bytes are uploaded, stored or parsed in this prototype.

## September 16: Apple component patterns

Reference lock: the user chose Apple component patterns for Placewise, explicitly kept the existing typography and colors, and chose to keep the browser prototype. All applicable phone UI uses `@ionic/react` 9.0.4 in iOS mode. Use Apple's [buttons](https://developer.apple.com/design/human-interface-guidelines/buttons), [menus](https://developer.apple.com/design/human-interface-guidelines/menus) and [toggles](https://developer.apple.com/design/human-interface-guidelines/toggles) as interaction references. Preserve Ionic component geometry and interaction states; map only the existing Placewise type and color roles. Keep the 44px touch floor, labels and focus states.

Navigation uses `IonHeader`, `IonToolbar`, `IonTitle` and `IonButtons`; the sidebar uses `IonMenu`. App, map and simulated keyboard actions use `IonButton`. History and route rows use `IonList`, `IonItem`, `IonLabel`, `IonNote` and `IonBadge`. Attachments and route editing use `IonPopover` within the phone. Subject and neighborhood selection use `IonSelect` / `IonSelectOption`; other forms use `IonRadioGroup` / `IonRadio`, `IonCheckbox`, `IonToggle`, `IonInput` and `IonTextarea`. App icons use `IonIcon` with Ionicons, and loading feedback uses `IonSpinner`. Keep attachment choices vertical above +, with focus return, keyboard traversal and reduced-motion support.

Decision: this adoption changes components only. The compact composer, third-line growth, conversation opening and existing routes remain intact; the withdrawn draggable sheet stays withdrawn. Retain all Placewise palette and type values. [Ionic React](https://ionicframework.com/docs/react/add-to-existing) is a third-party web library, not a native UIKit/SwiftUI or Figma kit import. Mapbox remains the map provider. Browser file/photo pickers and the actual mobile keyboard remain native OS features. The desktop keyboard keeps its simulated layout with Ionic keys. Marketing and documentation shell primitives remain outside this phone-app replacement.
